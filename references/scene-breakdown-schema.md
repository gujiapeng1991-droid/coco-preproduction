# 顺场表 Schema 参考（电影 / 剧集）

本文件是 `coco-scene-breakdown`（Coco影视顺场表）的列定义与统计口径。生成顺场表前先读它。

**一句话原则：一场一行，场号纯数字，不用 1A/1B。**

---

## 一、标准列（剧集版 · 17 列基础 + 角色列组）

| # | 列名 | 字段 key | 说明 | 示例 |
|---|------|----------|------|------|
| 1 | 集 | `ep` | 集数（仅剧集；**不合并，每行都显示**） | `3` |
| 2 | 场号 | `scene` | **顺序纯数字**，无字母后缀 | `1` / `12` |
| 3 | 日/夜 | `daynight` | 日 / 夜 / 晨 / 黄昏（自动配色） | `夜` |
| 4 | 内/外 | `inout` | 内 / 外（**与日/夜紧挨着**） | `内` |
| 5 | 主场景 | `mainset` | 大景，归组统计用；**值由脚本从场景解析**，排在场景之前 | `陈默家` |
| 6 | 场景 | `set` | `大景-具体位置` 两层写法，排在主场景之后 | `陈默家-客厅` |
| 7 | 氛围 | `mood` | 情绪基调，1-2 个词（词库见 scene-rules.md） | `温馨` |
| 8 | 内容梗概 | `synopsis` | **这场发生了什么**（场级概述，不是镜头描述） | `陈默回家，妻子已等了三个小时` |
| 9 | 页数 | `pages` | 0.1 页粒度（1 页 ≈ 1 分钟）；时长由它估算，不再单列 | `0.8` |
| 10 | 角色列组 | `roles`（自动展开） | **每个角色独占一列**：表头写**全名**，出场格里填**单字缩写**（剧本常用 4-8 人）；不提供 `roles` 时退化为 `cast` 单行文本。**固定排在页数之后** | 表头`陈默`，格内`陈` |
| 11 | 特约 | `extra` | 特约演员（说书人、货车司机这类，**不进角色列**） | `说书人` |
| 12 | 群众 | `mass` | 群众演员（**不进角色列**） | `食客若干` |
| 13 | 道具 | `props` | 关键道具（非全部，只列影响筹备的） | `旧怀表、离婚协议` |
| 14 | 视效 | `vfx` | 后期视效需求 | `窗外雨景合成` |
| 15 | 备注 | `note` | **唯一留给用户手填的列**，AI 一律留空 | `` |
| ~~—~~ | ~~累计页数~~ | ~~`cum`~~ | **v1.2 移除**（对统筹无独立价值，易与页数看混） | — |
| ~~—~~ | ~~时长(秒)~~ | ~~`sec`~~ | **v1.2 移除**（改由总页数 ×1 分钟估算） | — |

影片类（电影/短片）去掉 `ep` 即可。角色列展开后总列数 = 15 - 1 + 角色数。

> **v1.2 变更**：移除「时长(秒)」「累计页数」两列，并把「页数」挪到「内容梗概」之后、
> 角色列组之前。时长改由总页数估算（1 页 ≈ 1 分钟），统计 sheet 顶部给「预估总时长」；
> 旧 JSON 里若还写着 `sec` / `cum`，脚本会自动剔除并提示，不会渲染成空列。

> 填写约定：`extra / mass / props / vfx` 由 AI 依据剧本合理推断（剧本明写直接填，没明写按场景推断，
> 确实没有留空不硬编）；**只有 `note` 列留空给用户手填**。
> `mainset` 的值**不用手写**，脚本从 `set` 解析。可写进 `columns`
> 来指定顺序（推荐写 `mainset`，排在 `set` 之前），不写则脚本自动插在「场景」之前。
> 表内**不设「场次名」列**——剧本场景标题行原文（`内景·陈默家客厅·夜`）的信息
> 已由 日/夜 + 内/外 + 场景 三列覆盖，单独再列一遍是冗余。

## 二、与分镜表（storyboard-table）的列差异

| 分镜表列 | 顺场表怎么处理 |
|---------|--------------|
| 镜号 / 景别 / 摄法 / 分镜图 | **不要**（镜头级，本表不管） |
| 台词 / 音效 | **不要**（并入内容梗概，或交给分镜表） |
| 角色每人一列 ✓ | **保留同样的做法**（详见第五节） |
| 页数 | 保留，**每场都填** |
| 场景 | 保留，强化 `大景-具体位置`，并自动派生主场景列 |
| — | **新增**：主场景、氛围、内容梗概 |

两套表的角色列规范完全一致，缩写要跨表统一（都用 `陈` 而不是一处 `陈`、一处 `陈默`）。

## 三、页数评估（0.1 页粒度）

- **1 页 ≈ 1 分钟成片**：对白场基本符合；动作/特效场会拉长（1 页可拍出 2 分钟）
- 取值写小数：`0.1`（最细粒度 ≈ 6 秒）、`0.3`、`0.8`、`1.5`、`2`
- 兼容传统 1/8 页分数写法：`"1/8"` = 0.125、`"2 5/8"` = 2.625，脚本都能解析
- 有剧本：量该场在剧本页面的占比；无剧本：按预估秒数换算，6 秒 ≈ 0.1 页
- 每场都填页数；**页数是唯一的量纲**——时长、占比、归组排序全部由它推导

## 四、统计口径（统计 sheet 自动算）

| 指标 | 口径 |
|------|------|
| 总场数 | 数据行数（无字母后缀时与行数一致） |
| 总页数 | 全部行页数求和 |
| **预估总时长** | 总页数 × 1 分钟（经验值，表内标注口径） |
| 平均单场页数 | 总页数 ÷ 总场数 |
| 夜戏占比 | 日/夜 = 夜 的行数 ÷ 总行数（同时给**页数占比**） |
| 外景占比 | 内/外 = 外的行数 ÷ 总行数（同时给页数占比） |
| 主场景归组 | 按 `mainset` 聚合：场数 / 场次 / 页数 / 页数占比，**按页数降序** |
|  | 页数最多的主场景 = 主景，统筹优先安排 |
| 角色出场 | 每个角色：场数 / 场数占比 / 页数 / 页数占比，**按场数降序**（演员档期用） |

> v1.2 起统计表不再出现「秒数」列——时长列已移除，秒数全部为 0 没有意义。
> 统一换成**双占比**：场数占比看戏份密度，页数占比看实际体量，两者常常不一致
> （某角色场数多但都是过场戏，页数占比会明显低于场数占比）。

> 统计 sheet 由脚本自动生成，名为「场景统计」，不需要手写。

## 五、角色列规范（每人一列：表头全名 + 格内单字缩写）

- JSON 顶层 `"roles"` 声明全部角色；行内 `"roles": ["陈","林"]` 标该场出场者
  （也兼容 `"陈/林"` 字符串写法）
- **表头全名 / 格内缩写**（v1.3）：`roles` 写成 `["陈=陈默","林=林晚"]`，
  或者干脆不写全名——脚本会自动从 `meta.角色缩写` 对照表解析
  （`陈=陈默(男主) / 林=林晚(女主)` → 表头「陈默」「林晚」，格内「陈」「林」）
- `roles` 支持四种写法：`["陈=陈默"]` / `[{"abbr":"陈","name":"陈默"}]` /
  `{"陈":"陈默"}` / `["陈"]`（最后一种表头就显示缩写，向后兼容）
- **角色列组固定落在「页数」列之后**（v1.2）：`columns` 里的 `cast` 只作为占位符被替换掉，
  **它的位置不影响最终列序**——写在 pages 前面也不会让角色列跑到页数前面
- 每个角色独占一个窄列（宽按表头全名长度自适应，最小 4.6），出场格填**单字缩写**（加粗蓝字），不出场留空
- 统计 sheet 的「五、角色出场」也显示全名
- 角色名用姓名简称：陈默→`陈`，林晚→`林`；同场多人就多勾
- **缩写对照表必须写在 `meta.角色缩写`**：`"角色缩写": "陈=陈默(男主) / 林=林晚(女主) / 周=老周"`
- **特约 / 群众不进角色列**，填 `extra` / `mass`——角色列只放主要演员，否则表会太宽
- 不提供 `roles` 时，「出场人物」列保持单行文本（`"陈默、林晚"`）
- 与分镜表 skill（`storyboard-table`）是**同一套规范**，缩写要跨表一致

## 六、示例数据（JSON）

```json
{
  "title": "《雨夜来客》顺场表",
  "meta": { "集次": "S01E03", "编剧": "佚名", "版本": "v2",
            "页数口径": "0.1页粒度，1页≈1分钟",
            "角色缩写": "陈=陈默(男主) / 林=林晚(女主) / 周=老周" },
  "roles": ["陈", "林", "周"],
  "columns": ["ep","scene","daynight","inout","mainset","set","mood","synopsis","pages","cast","extra","mass","props","vfx","note"],
  "rows": [
    {"ep":"3","scene":"1","daynight":"夜","inout":"内","set":"陈默家-客厅",
     "mood":"温馨","synopsis":"陈默冒雨回家，林晚已等了三个小时，桌上饭菜凉透。",
     "roles":["陈","林"],"pages":0.5,"extra":"","mass":"","props":"凉掉的饭菜、湿雨衣","vfx":"","note":""},
    {"ep":"3","scene":"2","daynight":"夜","inout":"内","set":"陈默家-卧室",
     "mood":"压抑","synopsis":"两人移步卧室，林晚摊出离婚协议，陈默沉默不语。",
     "roles":["陈","林"],"pages":0.3,"extra":"","mass":"","props":"离婚协议","vfx":"","note":""},
    {"ep":"3","scene":"3","daynight":"夜","inout":"外","set":"老城区-巷口",
     "mood":"悬疑","synopsis":"黑衣人立在电话亭旁，看着二楼亮着的窗。",
     "roles":[],"pages":0.2,"extra":"","mass":"路人若干","props":"雨伞","vfx":"雨景合成","note":""}
  ]
}
```

> `columns` 用字段 key，脚本自动映射中文表头。`mainset` 的值自动解析、`cum` 自动累加。
> `cast` 留在 `columns` 里只是占位；角色列组固定落在「页数」之后，不跟 `cast` 的位置走。
> 也支持 CSV 输入（首行为中文表头列名）与 stdin（`-` 作输入路径）。
> `meta` 三种写法兼容：对象 `{"集次":"S01E03"}`（推荐）／字符串／数组。

完整样例见 `examples/sample_episode.json`（20 场 / 6 个角色），最小样例见 `examples/sample_min.json`（3 场）。
